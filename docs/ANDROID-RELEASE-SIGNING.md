# Android signing key custody

A new, stable Android application release key has been generated locally for application ID `com.motorline.pos`. It is an RSA 3072-bit private key in a PKCS#12 keystore, separate from the earlier Android Debug test certificate. `Motorline-1.1.0-release.apk` has been built and its APK v2 signature verified with this key. The public certificate SHA-256 fingerprint is `360BD350F970D3EFBB84584407BF4177D73350293CFC1CBA9127FD6F7C8D1DDF`.

Private signing material is stored only in the task workspace's `work/production-secrets/android/` directory. The directory has inheritance disabled and permits access only to the current Windows account and SYSTEM. `motorline-release.p12` contains the private key; `signing.json` contains its alias and randomly generated passwords. These files must never enter source control, an output archive, an APK, application assets, logs, or a chat message. They are intentionally excluded from deliverables.

Before distributing an operational Android package, the owner must make and verify an encrypted backup of the keystore and its metadata in an owner-controlled password vault or encrypted storage, with a separate protected recovery copy. Record custody and recovery ownership. Do not regenerate or discard this key when rebuilding: Android upgrades depend on the same application ID and signing identity. Losing the key may require uninstalling the app and losing unsynchronized local data unless an applicable managed signing recovery process exists.

For subsequent builds, load `MOTORLINE_ANDROID_KEYSTORE`, `MOTORLINE_ANDROID_STORE_PASSWORD`, `MOTORLINE_ANDROID_KEY_ALIAS`, and `MOTORLINE_ANDROID_KEY_PASSWORD` into the local build environment from secure storage, then run `android/gradlew.bat -p android assembleRelease` from `apps/android`. Do not paste passwords into shell command text or commit them in Gradle files. The Gradle configuration rejects partially supplied signing variables. Verify the resulting APK with Android SDK `apksigner verify --verbose --print-certs` and record the public certificate fingerprint with the release checksum.

A private release key is sufficient for an internally distributed Android APK; a purchased third-party certificate is not required. Public store distribution also follows that store's signing and publishing rules. The release build configures debugging and local cleartext HTTP as disabled, and its default API is `https://pos.cartunez.in/api/v1`. The address remains editable for an authorized installation. The fresh emulator install displayed that URL and denied `run-as` because the package is not debuggable.

The available emulator uses an Android `userdebug` system image. Chromium forces WebView debugging on that OS build independently of the application's setting, so the absence of a CDP endpoint must still be checked on a production Android `user` build. This behavior is documented in [Chromium's WebView debug implementation](https://chromium.googlesource.com/chromium/src/+/3546854f59..2e285ebae2) and [WebView debugging documentation](https://chromium.googlesource.com/chromium/src/+/HEAD/android_webview/docs/net-debugging.md). The packaged Capacitor settings disable WebView debugging and mixed content; this caveat concerns the development OS image, not an enabled application debug flag.

The release signature differs from the test APK's debug signature. Android will reject an in-place upgrade from that debug-signed package. On real counters, first synchronize all pending work and preserve local data before planning migration; do not uninstall a counter merely to bypass the signature mismatch. Emulator-only clean installation can be used for acceptance without touching a user's physical device.

The Windows installer is unsigned and the Android APK uses the development signing key. Production publisher signing requires the retailer's certificates and Android keystore. HTTPS verification used a local self-signed test certificate with explicit trust for the test. The retailer's production DNS, certificate chain, network exposure, and deployment credentials remain installation-specific checks.

Receipt PDF generation was exercised. No physical thermal printer was connected during verification. The Windows driver and Android print-service path are documented in `DEPLOYMENT.md`; paper size, cutter, drawer, and physical output require a printer acceptance test.

The demo catalog uses fictional compatibility rules. Production catalog source and licensing remain retailer responsibilities.

Card and UPI confirmation was tested using manually recorded external provider references. Unconfirmed provider payments remain pending. A retailer-specific payment webhook integration and live provider settlement checks require the retailer's provider credentials.

Executable checks are available as `scripts/test-windows-operations.cjs`, `scripts/test-windows.cjs`, and `scripts/test-windows-reconciliation.cjs`. Run them against a demonstration database with the seeded owner account. Set `MOTORLINE_INSTALLED_EXE` to the installed executable and optionally set `MOTORLINE_TEST_API` and `MOTORLINE_DEMO_PASSWORD`. The scripts create isolated verification users and write a profile plus results under `test-results`. These tests create real test transactions. Concise evidence is retained under `docs/test-results`.
